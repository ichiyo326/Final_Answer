`python/` 直下にある構成）を保ったまま実行すること。

## 実行方法

```bash
pip install requests beautifulsoup4 pandas
python3 1-1.py
```

```bash
pip install selenium requests pandas
python3 1-2.py
```

出力カラム: 店舗名, 電話番号, メールアドレス, 都道府県, 市区町村, 番地, 建物名, URL, SSL

実行時間の目安: 3秒待機×多数のリクエスト（一覧・詳細・URL確認）のため、
1-1.pyで10分前後、1-2.pyはブラウザ操作が入る分さらに時間がかかる（15〜20分程度）。

## 主な取得方針（本間さんのフィードバック反映）

- メールアドレス: ぐるなび店舗ページの「お店に直接メールする」リンクの `href`（`mailto:`）からのみ取得。掲載がなければ空欄。
- ホームページURL: 「お店のホームページ」を優先し、なければ「オフィシャルページ」。どちらも無ければ空欄。
  - 正常にアクセスできた場合はリダイレクト後の最終URLを保存。
  - CAPTCHA（`captcha.gnavi.co.jp`）やぐるなびの中継URLへ転送された場合、および接続失敗時は、
    転送前に取得していた外部サイトURLへフォールバックする（再アクセスによる突破は行わない）。
  - CAPTCHA/中継URLに`destination`等のパラメータで遷移先が埋め込まれている場合は、
    それを抽出して元の外部サイトURLと一致するかを確認し、ログへ記録する
    （`destination_param` / `destination_match`列。一致有無に関わらず、採用するURLは
    常に元の外部サイトURLのまま変えない）。
- SSL: 実際にCSVへ保存したURLを対象に証明書を検証する。
- 住所分割: 全角数字・「条/丁目/番/号/通」等の和式表記にも対応した正規表現で分割。
- 50件の確保: 一覧から必要件数の2倍（`CANDIDATE_MULTIPLIER = 2`）の候補URLを収集し、
  詳細取得に失敗した店舗があれば次の候補で埋め合わせる（詳細取得は最大2回まで再試行、
  無制限の再試行はしない）。
- リクエスト前の3秒待機: 一覧取得・詳細取得・ホームページURL確認のいずれも、リクエスト「前」に待機する。

## 実装の詳細（ぐるなびのDOM構造への依存）

以下は今回の実行時点でのぐるなび（r.gnavi.co.jp）のHTML構造に基づく実装になっている。
サイト側のマークアップが変わった場合、該当箇所の修正が必要になる。

- **店舗詳細URL判定**: `https://r.gnavi.co.jp/<5〜14文字の英数字コード（数字を含む）>/`
  の形式に一致するリンクを店舗詳細ページとみなす（`gnavi_common.DETAIL_URL_PATTERN`）。
- **ホームページURL**: リンクのテキストに「お店のホームページ」「オフィシャルページ」を
  含む`<a>`タグを探索する。`href`が`#`で実URLが無い場合、`data-o`属性にJSON形式
  （`{"a": "ドメイン/パス", "b": "スキーム"}`）で埋め込まれていることがあるため、
  そちらを優先的に見る。
- **住所**: hCardの`adr`マイクロフォーマット（`.adr`, `.region`, `.locality`）を
  優先的に使用し、無ければテキスト全体を正規表現（`gnavi_common.split_address`）で分割する。
- **次へボタン（1-2.pyのみ）**: `alt`属性が「次」で始まる画像を持つリンクを対象とする。

## Selenium版（1-2.py）で判明した2つの実装上の注意点

開発中に、requests版（1-1.py）と同じ店舗で結果が食い違う事例が見つかり、
以下2点を修正して解消した。

1. **ページ送りのクリックが実際の遷移に結びつかないことがある**
   `next_button.click()` を呼んでも `driver.current_url` が変化しないケースが
   実際にあった（原因未特定。サイト側のクリックハンドラの実装によるものと推測）。
   対策として、クリック後にURLが変化したかを確認し、変化していなければ
   `next_button`の`href`へ`driver.get()`で直接遷移するフォールバックを追加している
   （`click_and_wait_for_navigation`関数）。**課題文は「クリックしてページ遷移」を
   求めているため、クリックを主手段としつつ、クリックが機能しなかった場合のみ
   フォールバックする構成にしている。**
2. **`.text`では非表示テキストを拾えない**
   Seleniumの`.text`プロパティは画面上に実際に表示されているテキストしか返さない。
   「お店のホームページ」「オフィシャルページ」のリンクはアイコン画像で、
   ラベル文字列自体はCSSで視覚的に隠されている（かつ、間に空白が入ることがある）ため、
   `.text`では検出できなかった。`textContent`＋空白除去で取得するよう修正している
   （`visible_or_hidden_text` / `normalize_label_text`関数）。

## 既知の制限事項・懸念点

- **メールアドレスの取得件数が少ない**: 本番実行（東京エリア50件）では、
  50件中1件しかメールアドレスが取得できていない。個別に確認したところ、
  対象店舗の多くに「お店に直接メールする」のmailto:リンク自体が存在しないためで、
  取得ロジックの不具合ではない（LIGNOSA CAFE・Beer Bar Ma Maisonを個別に実行し、
  該当リンクがある店舗では期待通り取得できることを確認済み。`tests/test_specific_shops.py`参照）。
- **CAPTCHA・接続失敗時のフォールパックは実データでの動作実績がない**: 本番の
  50件実行では、CAPTCHAにも接続失敗にも一度も遭遇しなかった（3秒待機と
  即時フォールバックにより、ボット判定を回避できていると考えられる）。
  そのため`gnavi_common.py`のフォールバックロジックは`tests/test_gnavi_common.py`
  による単体テスト（擬似的にCAPTCHA・接続エラー・SSL失敗を発生させる）でのみ検証済みで、
  「本物のケースに遭遇して正しく動いた実績」ではない。
- **東京エリアのみでの実行**: `SEARCH_URLS`に東京エリアのみを指定して実行しているため、
  `北海道旭川市2条通8-569-1`のような住所パターンは実際にスクレイピングした50件には
  含まれていない（`gnavi_common.split_address`の単体テストとしては別途検証済み）。
- **サイトのHTML構造への依存**: 上記「実装の詳細」に記載の通り、ぐるなび側の
  マークアップ変更に弱い実装になっている。
